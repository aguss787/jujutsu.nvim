INTRODUCTION                                             *jujutsu-introduction*

jujutsu.nvim is a Neovim plugin for the Jujutsu version control system.
It provides interactive log, bookmark list, and operation log buffers with
keymaps for common jj operations.

==============================================================================
REQUIREMENTS                                             *jujutsu-requirements*

- Neovim 0.10+
- `jj` (https://github.com/jj-vcs/jj) installed and in `$PATH`
- noice.nvim (optional, for progress notifications on fetch/push)

==============================================================================
SETUP                                                           *jujutsu-setup*

Add the following to your Neovim config: >lua

  require("jujutsu").setup()
<

==============================================================================
COMMANDS                                                     *jujutsu-commands*

                                                                          *:Jj*
:Jj [subcommand]

  Open a jujutsu buffer. Available subcommands:

  `:Jj`           Open the log buffer (same as `:Jj log`)
  `:Jj log`       Open the log buffer
  `:Jj bookmark`  Open the bookmark list buffer
  `:Jj op`        Open the operation log buffer

  The log, bookmark, and op buffers share the same window — opening one
  replaces the other in the same split.

==============================================================================
SHARED KEYMAPS                                         *jujutsu-shared-keymaps*

These keymaps are available in the log, bookmark, and op buffers:

  `q`       Close the buffer
  `gl`      Switch to log buffer
  `gb`      Switch to bookmark buffer
  `go`      Switch to op buffer
  `<C-r>`   Refresh the buffer

==============================================================================
LOG BUFFER KEYMAPS                                       *jujutsu-log-keymaps*

  `<CR>`    `jj edit` the revision under cursor
  `m`       Toggle mark on revision under cursor (see |jujutsu-marks|)
  `M`       Clear all marks
  `n`       `jj new` from revision(s)
  `a`       `jj abandon` revision(s)
  `s`       `jj squash` into parent, or into single marked rev
  `r`       `jj rebase -s` revision onto marked destination(s)
  `R`       `jj rebase` with source/destination mode picker
  `u`       `jj undo`
  `d`       Edit revision description
  `p`       `jj duplicate --onto` marked destination(s)
  `P`       `jj duplicate` with destination mode picker
  `bs`      `jj bookmark set` on revision under cursor
  `bd`      `jj bookmark delete` on revision under cursor
  `bm`      `jj bookmark move` from marked rev(s) to cursor rev
  `bM`      `jj bookmark move -B` (allow backwards/sideways)
  `bt`      `jj bookmark track` (appends `@origin` if no `@`)
  `bT`      `jj bookmark untrack` (appends `@origin` if no `@`)
  `gf`      `jj git fetch`
  `gp`      `jj git push -r` revision(s)
  `gP`      `jj git push --all --deleted`

REBASE MODE PICKER (`R`) ~

Opens two selection menus to choose the rebase mode:

  Source:       `-s` (revision + descendants)
                `-r` (single revision only)
                `-b` (entire branch)

  Destination:  `-d` (rebase onto)
                `--before` (insert before)
                `--after` (insert after)

DUPLICATE MODE PICKER (`P`) ~

Opens a selection menu to choose the destination mode:

  `--onto`            duplicate onto destination
  `--insert-after`    insert after destination
  `--insert-before`   insert before destination

==============================================================================
BOOKMARK BUFFER KEYMAPS                             *jujutsu-bookmark-keymaps*

  `<CR>`    `jj edit` bookmark under cursor and switch to log buffer
  `n`       `jj new` from the bookmark under cursor
  `d`       `jj bookmark delete` the bookmark under cursor
  `t`       `jj bookmark track` the bookmark under cursor (`@origin`)
  `T`       `jj bookmark untrack` the bookmark under cursor (`@origin`)
  `r`       Toggle between local only and all remote bookmarks
  `gf`      `jj git fetch`
  `gp`      `jj git push -b` the bookmark under cursor
  `gP`      `jj git push --all --deleted`
  `u`       `jj undo`

==============================================================================
OP BUFFER KEYMAPS                                           *jujutsu-op-keymaps*

  `u`       `jj undo`

==============================================================================
MARKS                                                           *jujutsu-marks*

Press `m` to mark revisions. Marks are used differently depending on the
operation:

  Source revisions ~
    `n`, `a` act on all marked revisions instead of the cursor revision.

  Destination revisions ~
    `r`, `R`, `p`, `P` use marks as the destination to rebase/duplicate onto.
    `s` squashes the cursor revision into the single marked destination.
    `bm`, `bM` move bookmarks from marked revision(s) to the cursor revision.

Press `M` to clear all marks.

CONFIGURATION                                           *jujutsu-configuration*

Pass a table to |jujutsu-setup| to override defaults: >lua

  require("jujutsu").setup({
    split = "horizontal",
    keymaps = {
      log = {
        edit = "e",
      },
      bookmark = {
        track = "T",
      },
    },
  })
<

                                                             *jujutsu-split*
split ~
  Type: `string`
  Default: `"vertical"`
  Values: `"vertical"` | `"horizontal"`

  How to split the window when opening a buffer. `"vertical"` opens a
  side-by-side split, `"horizontal"` opens a top/bottom split.

                                                       *jujutsu-cache-gpg*
cache_gpg ~
  Type: `false` | `"on-push"` | `"all"`
  Default: `false`

  Controls when the plugin pre-caches your GPG passphrase in gpg-agent.
  If the passphrase is not cached, you are prompted to enter it (characters
  are hidden). The passphrase is then cached via a loopback signing call
  before the jj command proceeds.

  `false`      No GPG passphrase caching.
  `"on-push"`  Check before push operations only.
  `"all"`      Check before all jj operations.

  This prevents jj from blocking on an interactive GPG prompt that cannot
  be handled inside Neovim.

  Requires `gpg` in `$PATH` and `allow-loopback-pinentry` in
  `~/.gnupg/gpg-agent.conf`. After adding the line, reload the agent with
  `gpgconf --kill gpg-agent`. >lua

    require("jujutsu").setup({
      cache_gpg = "on-push",
    })
<

                                                           *jujutsu-keymaps*
keymaps ~
  Type: `table`
  Keymaps are split into `log`, `bookmark`, and `op` sub-tables. Only the
  keys you specify are overridden; the rest keep their defaults.

  Set a keymap to `false` to disable it: >lua

    require("jujutsu").setup({
      keymaps = {
        log = {
          abandon = false,
        },
      },
    })
<
